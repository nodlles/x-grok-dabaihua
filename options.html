基本设置

决定悬停之后会发生什么：用哪个引擎、卡片长什么样。

关掉之后不再解读，X 原生的抽屉也交还给它自己。

解读引擎

Grok 复用你在 X 的登录态；第三方 API 用你自己的 Key 直连；演示只看界面；学习只抓请求结构。

只有悬停弹出的那张卡片会变；这个设置页跟着系统深浅色走。

鼠标在推文上停多久之后开始解读。

解读期间把它藏起来，结束或关闭卡片后还原。只有 Grok 引擎用得上。

默认那组选择器猜不中时再填：右键抽屉 → 检查，把它的 CSS 选择器贴进来。留空即用内置规则。

02

解读专家

换个专家就是换一种讲法。提示词按「做什么 + 不许跑偏 + 不许编」写，你也能改。

占位符：{{text}} 正文、{{url}} 原帖链接、{{author}} 作者、 {{handle}} 账号、{{date}} 时间、{{title}} 文章标题、 {{expert}} 专家名、{{service}} 服务名、{{model}} 模型名。 不写 {{text}} 时，正文会自动接在末尾。

03

AI 服务

任何 OpenAI 兼容的 /chat/completions 接口都能用。切到「第三方 API」引擎时走这里的配置。

内置的服务可以改地址与模型，也能另存一套自己的。

填到 /chat/completions 为止；后台会带上 Authorization: Bearer 发过去。

只存在本机 chrome.storage，不经过插件作者，也不会随打包或分享泄露。

填服务商给出的模型名，例如 deepseek-chat。

越低越稳，越高越发散。解读类任务 0.2 到 0.4 就够了。

每个请求都会带上的前置要求，管住语气和「不许编造」这条底线。

发请求前会先申请该域名的访问权限，浏览器会弹一次确认框。

05

数据与隐私

Grok 引擎下，悬停解读和追问会把帖子文本、链接与相关问答发给 X/Grok，用的是你的 Grok 额度。第三方 API 引擎下，同样的内容发给你自己配置的接口，用你自己的额度。设置、API Key 和解读缓存都只留在本机。

请求捕获默认关闭，开启后也只在学习模式里生效。关掉捕获不会删除已有记录，要清空请点上面的「清空」。
